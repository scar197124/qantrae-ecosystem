QANTRAE TRANSPARENCY

Warnings should not be magic.

QANTRAE is built to expose useful reasoning: what was examined, which signals mattered, what the system could not know, and where the user should verify before acting.

Scores are indicators

A risk score is a structured interpretation of signals, not proof. A low score cannot guarantee safety and a high score does not replace verification or professional analysis.

Different layers, different evidence

Lite and Sense work with lighter visible/local signals. Shield and IT can present stronger evidence and technical context. The interface should make that difference clear instead of presenting every result as equivalent.

External intelligence

When IT uses server-assisted or public intelligence sources, availability and quality can vary. A failed lookup is not the same thing as a clean target, and the product should communicate unavailable evidence separately from a safe result.

False positives and negatives

No automated scanner eliminates either. Attack techniques change, benign infrastructure can look unusual, and malicious infrastructure can appear normal. QANTRAE is decision support, not certainty.

Our transparency rule

If QANTRAE asks a user to distrust, pause, or investigate something, the interface should provide enough visible context to understand why. If the system does not have enough evidence, it should say that rather than manufacture confidence.

Product-specific Transparency pages remain important because they can explain the exact signals and limitations of each layer in more detail than this ecosystem-wide statement.
